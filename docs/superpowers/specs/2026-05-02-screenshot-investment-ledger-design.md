# 截图识别投资账本设计方案

## 目标

构建 AssetFlow 第一版：通过 iPhone 截图导入投资交易和资产信息，使用云端 OCR 或多模态识别抽取结构化数据，更新本地资产账本，并按照用户提供的 `导入模板.xlsx` 格式导出交易流水。

第一阶段优先适配华泰涨乐全球通。富途证券和华宝证券作为后续券商适配器接入，复用同一套上传、识别、账本、校验和导出流程。

## 范围

### 本期包含

- iPhone 通过快捷指令在局域网上传截图。
- 优先支持华泰涨乐全球通的三类截图：
  - 成交记录或历史成交页
  - 持仓页
  - 资金或现金页
- 调用云端 OCR 或多模态识别服务，完成截图分类和字段抽取。
- 本地 SQLite 保存截图、识别结果、候选交易、正式交易、持仓快照、资金快照、校验差异和导出任务。
- 高置信度、非重复、字段完整的交易自动入账。
- 低置信度、字段缺失、疑似重复或校验不一致的记录进入人工确认队列。
- 用正式交易流水推导持仓，再和持仓/资金截图做差异校验。
- 按提供的 xlsx 模板导出正式交易流水。
- 默认按币种拆分 xlsx 导出文件。
- 额外提供 CSV 或普通 Excel 备份导出。

### 本期不包含

- 自动控制券商 App。
- 自动登录券商账户。
- 保存券商登录密码。
- 绕过验证码、短信验证、设备绑定或券商风控。
- 自动下单或交易。
- 完整投资分析报表。
- 公网截图上传。

## 关键决策

- 第一版走“截图上传 + 云端识别”，不做真机 App 自动化控制。
- iPhone 端使用快捷指令上传截图。
- AssetFlow 服务只在同一 Wi-Fi 局域网内访问。
- SQLite 是本地账本的唯一可信数据源。
- 成交记录负责还原交易过程，持仓和资金截图负责校验结果。
- xlsx 导出通过复制 `导入模板.xlsx` 母版生成，保留表头和样式，从第 2 行开始写真实交易。
- 华泰涨乐全球通作为第一个 broker adapter，券商特有解析逻辑和通用账本逻辑分离。

## 架构

AssetFlow 第一版分为五个模块。

### 上传模块

上传模块提供局域网 HTTP 接口，供 iPhone 快捷指令调用。

职责：

- 接收局域网内的图片上传。
- 校验上传 token。
- 接收券商标识，第一版支持 `htsc_global`，代表华泰涨乐全球通。
- 拒绝非图片文件。
- 限制单文件大小。
- 为图片计算内容哈希。
- 识别重复上传的同一张截图。
- 保存上传元数据到数据库。
- 按配置保存或删除原始截图。

第一版只支持局域网上传。公网 HTTPS、Cloudflare Tunnel、云服务器入口都作为后续扩展。

### 识别模块

识别模块把截图发送给云端 OCR 或多模态模型，并把结果规范化。

职责：

- 将截图分类为 `trade_history`、`positions`、`cash` 或 `unknown`。
- 从截图中抽取结构化字段。
- 保存云端服务返回的原始 JSON，方便审计和排错。
- 生成候选交易、持仓快照或资金快照。
- 在可用时保存记录级和字段级置信度。
- 识别失败时只记录错误，不写入正式交易账本。

第一版实现 `htsc_global` 识别器。后续富途证券、华宝证券识别器需要输出相同的标准结构。

### 账本模块

账本模块是正式金融记录的来源。

职责：

- 保存上传记录。
- 保存原始识别结果。
- 保存候选交易。
- 保存正式交易流水。
- 保存持仓快照和资金快照。
- 保存校验差异。
- 保存导出任务历史。
- 生成稳定的交易去重键。
- 保留正式交易与来源截图、来源识别结果之间的关联。

只有正式交易流水可以参与资产计算和 xlsx 模板导出。

### 校验模块

校验模块负责把交易流水推导出的资产状态，与截图识别出的持仓/资金快照进行对比。

职责：

- 根据正式交易流水计算理论持仓。
- 按券商、账户别名、市场、证券代码、币种匹配最新持仓快照。
- 在信息足够时比较现金变动和资金快照。
- 差异只生成校验问题，不自动改历史交易。
- 差异保持可见，直到用户修正、忽略或补充数据。

这个设计避免单张截图识别错误时静默污染历史账本。

### 导出模块

导出模块从正式交易流水生成文件。

职责：

- 复制用户提供的 `导入模板.xlsx`。
- 保留第一行表头和模板样式。
- 删除或覆盖模板中的示例行。
- 从第 2 行开始写入真实交易。
- 严格保持模板列顺序。
- 默认按币种拆分导出。
- 保存导出任务的输出路径、行数、状态和失败原因。
- 缺少必填字段的交易不写入 xlsx，并在导出结果中列出。

设计阶段读取到的模板信息：

| 列 | 表头 |
| --- | --- |
| A | 成交日期 |
| B | 成交时间 |
| C | 证券代码 |
| D | 证券名称 |
| E | 交易类别 |
| F | 成交数量 |
| G | 成交价格 |
| H | 发生金额 |
| I | 证券余额 |
| J | 佣金 |
| K | 费用 |
| L | 重要提醒 |

## 数据流

1. 用户在 iPhone 上打开华泰涨乐全球通，截取成交、持仓或资金页面。
2. 用户把截图分享到 AssetFlow 快捷指令。
3. 快捷指令把图片、上传 token、券商标识发送到本地 AssetFlow 上传接口。
4. AssetFlow 保存上传记录，计算图片哈希，并判断是否重复上传。
5. 新图片进入识别队列，发送给云端 OCR 或多模态识别服务。
6. 识别模块判断截图类型，并抽取结构化字段。
7. 成交截图生成候选交易；持仓截图生成持仓快照；资金截图生成资金快照。
8. 候选交易经过字段规范化、置信度检查、金额方向检查和去重检查。
9. 高置信度、非重复、字段完整的候选交易自动转为正式交易。
10. 低置信度、字段缺失、疑似重复或金额方向异常的记录留在确认队列。
11. 正式交易流水更新本地账本中的计算状态。
12. 最新持仓和资金快照与账本推导状态进行差异校验。
13. 差异写入校验问题，等待用户处理。
14. 用户发起导出时，系统用正式交易流水生成符合模板的 xlsx 文件。

## 交易规范化规则

### 交易类别

识别出的交易含义统一映射为内部交易类型，并在导出时转换为模板需要的中文值。

| 识别含义 | 内部类型 | 模板值 |
| --- | --- | --- |
| 买入 | `buy` | 买入 |
| 卖出 | `sell` | 卖出 |
| 分红 | `dividend` | 分红 |
| 入金或转入 | `cash_in` | 转入 |
| 出金或转出 | `cash_out` | 转出 |
| 费用调整 | `fee` | 费用 |
| 手动调整 | `adjustment` | 调整 |

第一版 xlsx 模板导出优先支持 `buy` 和 `sell`。其他类型可以先进入账本，如果目标导入模板不支持，则从模板导出中排除并在导出结果中说明。

### 金额方向

模板导出规则：

- 买入交易的 `发生金额` 写负数。
- 卖出交易的 `发生金额` 写正数。
- 佣金和费用字段以正数成本保存。
- `费用` 是不含佣金的其他费用合计。
- 如果截图只提供净发生金额，则 `net_amount` 直接采用截图金额，佣金和费用留空，除非截图明确识别出费用明细。

### 币种

模板没有币种列，因此 AssetFlow 默认按币种拆分 xlsx 导出文件。

默认文件名包含券商、日期范围和币种，例如：

```text
assetflow-htsc_global-20260501-20260531-HKD.xlsx
assetflow-htsc_global-20260501-20260531-USD.xlsx
```

如果用户选择合并导出，导出任务会记录涉及的币种，但模板行本身仍无法表达币种。

### 去重键

交易去重键由以下字段生成：

```text
broker + account_alias + trade_date + trade_time + symbol + trade_type + quantity + price + net_amount + currency
```

如果 `trade_time` 缺失，则使用日期、证券代码、交易类型、数量、价格、金额和币种生成弱去重键。弱去重键命中的记录更倾向进入“疑似重复”队列，而不是自动确认。

## xlsx 模板映射

正式交易映射到模板字段如下：

| 模板表头 | 来源字段 | 格式 |
| --- | --- | --- |
| 成交日期 | `trade_date` | `YYYYMMDD` |
| 成交时间 | `trade_time` | `HH:MM:SS`，未知则留空 |
| 证券代码 | `symbol` | 是否带市场后缀由导出适配器决定 |
| 证券名称 | `security_name` | 文本 |
| 交易类别 | `trade_type` | `买入`、`卖出` 等模板值 |
| 成交数量 | `quantity` | 数值 |
| 成交价格 | `price` | 数值，尽量保留 4 位小数 |
| 发生金额 | `net_amount` | 数值，买入为负，卖出为正 |
| 证券余额 | `position_balance_after` | 数值或留空 |
| 佣金 | `commission` | 数值或留空 |
| 费用 | `fees` | 数值或留空 |
| 重要提醒 | 空 | 默认留空 |

导出校验规则：

- `trade_date`、`symbol`、`security_name`、`trade_type`、`quantity`、`price`、`net_amount` 是模板导出的必填字段。
- 缺少必填字段的记录不写入 xlsx，并在导出任务结果中列出。
- 模板示例行不进入输出文件。
- 写入前校验模板表头。如果用户选择的模板和预期表头不一致，导出失败并提示预期表头。

## 人工确认队列

人工确认队列用于避免识别错误静默入账。

以下情况进入确认队列：

- 截图类型为 `unknown`。
- 必填字段缺失。
- 记录置信度低于自动确认阈值。
- 证券代码、交易类别、数量、价格、金额或币种等关键字段置信度低。
- 命中完全重复。
- 命中疑似重复。
- 金额方向和交易类别冲突。
- 持仓或资金快照校验发现差异。

确认队列支持的操作：

- 确认候选交易。
- 编辑候选交易并确认。
- 忽略候选交易。
- 重新识别。
- 标记校验问题已解决。
- 忽略校验问题。

## 安全和隐私

- 上传接口必须带 token。
- 第一版只绑定用户选择的局域网地址。
- 服务拒绝非图片上传。
- 服务限制单文件大小。
- 系统不请求、不保存券商登录密码。
- 第一版不做券商 App 自动化控制。
- 云端识别 API key 存在本地配置或环境变量。
- API key 不写入日志、xlsx 文件或 CSV 文件。
- 普通日志不记录完整截图内容、完整账户标识或云服务密钥。
- 原始截图保留策略可配置。
- 第一版默认保留截图用于审计，直到用户删除或修改保留策略。

## 错误处理

### 上传错误

- token 无效：拒绝请求，不创建上传记录。
- 文件类型不支持：拒绝请求，不创建上传记录。
- 文件过大：拒绝请求，不创建上传记录。
- 图片哈希重复：标记为重复上传，默认不再次识别。

### 识别错误

- 云端服务超时：识别状态标记为失败，允许重试。
- 云端返回非法 JSON：保存可用的原始响应，标记失败，允许重试。
- 截图无法分类：标记为 `unknown`，进入确认队列。
- 必填字段缺失：能形成候选记录时进入确认队列；无法形成候选记录时显示识别失败。

### 账本错误

- 完全重复交易：不新增正式交易。
- 疑似重复交易：保留候选记录，等待人工确认。
- 金额方向异常：保留候选记录，等待人工确认。
- 不支持的币种：保留候选记录，等待人工确认。

### 导出错误

- 模板不存在：导出任务失败，提示重新选择或恢复模板。
- 表头不匹配：导出任务失败，显示预期表头。
- 交易缺少必填字段：跳过该交易，并写入导出结果。
- 文件写入失败：导出任务失败，数据库保存错误信息。

## 测试和验收标准

### 上传

- iPhone 和电脑在同一 Wi-Fi 下时，快捷指令可以上传截图。
- AssetFlow 能保存上传元数据和图片哈希。
- 同一张截图重复上传不会生成重复正式交易。

### 识别

- 华泰涨乐全球通成交截图能分类为 `trade_history`。
- 华泰涨乐全球通持仓截图能分类为 `positions`。
- 华泰涨乐全球通资金截图能分类为 `cash`。
- 识别结果保存原始 JSON 和规范化 JSON。
- 低置信度或字段不完整的记录进入确认队列，而不是正式交易表。

### 账本

- 一笔高置信度买入交易能生成一条正式交易。
- 一笔高置信度卖出交易能生成一条正式交易。
- 缺少证券代码、数量、价格、金额或币种时不能自动确认。
- 完全重复截图不会生成重复正式交易。

### 校验

- 交易流水推导出的持仓数量和最新持仓快照一致时，不生成差异。
- 交易流水推导出的持仓数量和最新持仓快照不一致时，生成一条校验问题。
- 校验问题不改写历史交易流水。

### xlsx 导出

- 导出文件基于 `导入模板.xlsx` 复制生成。
- 第一行表头保持不变。
- 示例行被删除或覆盖。
- 真实交易从第 2 行开始写入。
- 写入列顺序严格为：
  `成交日期`、`成交时间`、`证券代码`、`证券名称`、`交易类别`、`成交数量`、`成交价格`、`发生金额`、`证券余额`、`佣金`、`费用`、`重要提醒`。
- 默认按币种拆分导出文件。
- 缺少必填导出字段的交易被排除，并在导出结果中说明。

### 安全

- 不带 token 的上传请求会被拒绝。
- 非图片上传会被拒绝。
- 系统不保存券商密码。
- 云端识别 API key 不出现在日志或导出文件中。
